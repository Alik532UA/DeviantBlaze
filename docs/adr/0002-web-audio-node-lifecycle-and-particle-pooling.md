# ADR 0002: Web Audio Node Lifecycle and Particle Pool Memory Architecture

- **Статус**: Прийнято
- **Дата**: 2026-11-09
- **Контекст**: selection_criteria/v10, product_criteria/v10

## Контекст та Проблема

Портал `DeviantBlaze` містить високопродуктивні інтерактивні аудіовізуальні компоненти:

1. Web Audio API синтезатор фортепіано з 4 пресетами (`grand_piano`, `analog_lead`, `ambient_pad`, `sub_bass`).
2. Повноекранний VJ-візуалізатор та фоновий рендерер частинок на Canvas 2D із частотою 60fps.

Без чіткого керування життєвим циклом аудіовузлів виникає витік пам'яті (`AudioNode` не збираються GC, якщо не від'єднані через `disconnect()`), а часте створення об'єктів частинок у циклі `requestAnimationFrame` викликає регулярні лаги при спрацьовуванні Garbage Collector.

## Прийняті рішення

1. **Життєвий цикл аудіовузлів**:
   - Кожна зіграна нота створює ізольований ланцюг: `OscillatorNode -> GainNode (ADSR) -> BiquadFilterNode -> AnalyserNode -> Destination`.
   - Після закінчення фази Release (`envelope.release`) за таймером викликається `node.stop()` та обов'язковий `node.disconnect()`.

2. **Пул частинок та плоскі типізовані масиви**:
   - Частинки візуалізатора використовують фіксований пул або типізовані масиви `Float32Array` для зберігання координат `(x, y, vx, vy, alpha, size)` замість динамічного виділення об'єктів у кадрі.

3. **Стійкість рендерингу та Error Boundaries**:
   - Увесь шар відображення `src/routes/+layout.svelte` загорнуто в `<svelte:boundary>` з компонентом `ErrorFallback.svelte`.
   - Клієнтський обробник `src/hooks.client.js` підтримує діагностику та перезавантаження застарілих чанків через `staleBuild.js`.

## Наслідки

- Стабільні 60 FPS без періодичних мікрофризів на слабких пристроях.
- Відсутність витоків пам'яті Web Audio при тривалій сесії гри на фортепіано.
- Повний захист від падінь рендерингу при некоректних діях користувача або збоях драйверів звуку.
